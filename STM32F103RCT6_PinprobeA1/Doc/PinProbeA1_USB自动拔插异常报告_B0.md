# PinProbeA1 USB自动拔插异常报告 B0

文档更新时间：2026-10-10 ｜ 版本 B0 ｜ 依据：连续开关门指令测试日志（设备时间 T+32098.629～T+32145.304）与现场机构说明。

:::chips
现象 | 门开到位后 USB 未自动回退
工况 | 上位机连续指令开关门
判定 | 自动回退未执行（非"发出后未到位"）
改进方向 | 门位置自纠正 + 回退条件调整
:::

:::note
**结论：** 不是 USB 气缸、门气缸或到位传感的故障——最后一次未被打断的关门在 3850 ms 内正常到位。自动回退只在"门已开到位 **且** 设备处于空闲待机状态"时执行；连续指令开关门时，关门每次都在行程约 74% 处被下一条开门指令打断，设备流程始终停在"关门进行中"，自动回退因此从未执行。
:::

## 一、异常现象与判定

| 项目 | 内容 |
| --- | --- |
| 现象 | 门开到位后 USB 保持插入、未自动回退；整个记录中没有 USB 气缸动作，也没有任何告警 |
| 工况 | 上位机按约 3.0 s 周期交替下发 `CONFigure:CYLInder1 OPEN` / `CLOSE`；随后补发一次开门指令 |
| 排除 | !!USB 气缸或到位传感故障!!：该路在整个记录中没有动作；!!门或气缸故障!!：最后一次关门 3850 ms 正常到底 |
| 判定 | 自动回退**未被执行**（回退指令没有发出），不是"发出后未到位" |

## 二、证据链（以下均为设备日志原文，可逐条复核）

| 观测项 | 日志记录 | 说明 |
| --- | --- | --- |
| 流程停留 | `RUNNING -> COMPLETE stay=57550ms` | 设备进入"关门进行中"的时刻 = T+32084.754 s |
| 记录窗口 | T+32098.629 → T+32142.304（44 s） | 整段都落在那**同一次**"关门进行中"之内 |
| 门开到位 | `CLOSE_PHASE ... phase=0` 出现 8 次 | 门到位时，设备流程仍处于"关门进行中" |
| 门关到底 | `phase=2` 仅 1 次，紧随 `CLOSE_DONE duration=3850ms` | 全行程 3850 ms（末段为缓冲棉条减速段），机构与传感正常 |
| 指令周期 | `CLOSE` → `OPEN` = 3.0 s（6 次循环一致） | 3.0 s < 3.85 s，**必然**在约 74% 处被打断 |
| USB / 安全 | 0 条 `cyl=2`；无 `EMERGENCY`、无 `LASER` | 自动回退未执行；安全保护未介入 |

## 三、原因分析

**触发条件：** 门体末段装配缓冲棉条，门到位前需减速缓冲，末段限位触发偏慢，全行程因此需要 3850 ms（现场机构说明，与设备记录的行程时间一致）。而上位机指令周期为 3.0 s，6 次关门全部在约 74% 处被下一条开门指令打断——**开门指令恰好落在末段缓冲区内**；而"门关到底"是"关门进行中"这一状态唯一的正常结束方式。

**直接原因：** 自动回退的执行条件是"门已开到位 **且** 设备处于空闲待机状态"，而设备流程在 44 s 内始终停留在"关门进行中"，自动回退的判定一次都没有执行。这与"USB 显示已插入"并不矛盾——该状态由"输出 + 到位传感"推导，其中有一条只看门上限位传感的兜底判断，所以门开着、USB 插着时，状态查询仍显示正常。

改进因此分两处：门的位置需要能自动纠正；回退的判定不应只依赖单一的流程状态。见下章。

## 四、优化方案

**目标：** 门一旦开到位就保证 USB 回到回退位置；门的位置与设备流程状态不一致时，设备应自行纠正，而不是停在中间状态等待复位。

| 编号 | 改进项 | 改进后 | 现场效果 |
| --- | --- | --- | --- |
| O1 | 位置纠正 | 门已开到位、且没有正在执行的关门动作、也没有待执行的关门意图时，流程自动回到空闲待机 | 中途开门、断电复气后开门都能自行恢复到可操作状态；判定依据是门的位置而不是时间，不受末段缓冲减速影响 |
| O2 | 回退条件调整 | 执行条件改为"门已开到位 + USB 仍处于插入状态 + 无关门意图" | 门开到位后 USB 必定回退，不再依赖单一流程状态 |
| O3 | 异常提示 | 未执行与未到位分别给出明确告警，并带原因与耗时 | 可一眼分清"没有执行"与"执行失败" |
| O4 | 失败可恢复 | 安全条件满足时允许自动重试一次；仍失败则告警并保持状态可查询 | 偶发一次不到位，不会让 USB 永久留在插入状态 |

安全保护不变：急停、激光防夹、断电回锁与到位反馈都不受影响；接口指令与返回值定义不变；自动回退仍以"门已开到位"为安全前提。

**自检方法（关门到位、绿灯亮起后发一次开门指令，再依次查询）：** `READ:SYSTem:STATe?` 期望回到 `IDLE`；`READ:CYLInder2:STATe?` 期望数秒内变为 `OPENED`；若显示 `CYL ERR`，属"已执行但未到位"，请按告警原因检查回退机构与到位传感。

## 五、验收与关注点

| 编号 | 场景 | 通过判据 |
| --- | --- | --- |
| A1 | 关门到位后发开门指令 | USB 自动回退，状态查询与实际位置一致 |
| A2 | 关门过程中发开门指令 | 门开到位后流程回到空闲待机，并自动回退 |
| A3 | 人为制造回退到位传感异常 | 出现明确告警（含原因），状态可查询 |
| A4 | 制造一次回退不到位后恢复正常 | 自动重试一次后到位；仍失败则告警且保持可操作 |

**关注点：** ① 门体末段装配缓冲棉条、到位前减速明显，设备对关门时间的判断（含防夹检测窗口）以完整行程为准——本次记录的 3850 ms 即为含缓冲的全行程时间；② 连续指令开关门（关门未完成即反向开门）不属于正常操作工况，且开门指令落在缓冲段内，对机构与气压损耗更大，建议上位机脚本改为"等到位再发下一条"；③ 该自动流程的实机验收基线将随 A1～A4 一并建立。
